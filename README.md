# دریل 🎯

> **نصب یک‌خطی** (مک/لینوکس — node و git را خودش چک می‌کند):
> ```bash
> curl -fsSL https://raw.githubusercontent.com/koolfox/drill/main/install.sh | bash
> ```
> بعد در OpenCode: `/drill یک تمرین تایپ بده` — همین. جزئیات در [نصب](#نصب-سراسری).

یک **دریل روی صفحه** برای برنامه‌نویس‌ها: مدل (OpenCode) کد را به‌صورت
تمرین تایپ آماده می‌کند، روی صفحه بالا می‌آید، شما تایپ می‌کنید — هم به‌عنوان
تمرین (سرعت/دقت) و هم به‌عنوان کار واقعی (نوشتن در ویرایشگر خودتان)، و در پایان
OpenCode خبر داده می‌شود و کار را ادامه می‌دهد.

```
شما: /drill یک تست برای ماژول X بنویس
مدل: تحقیق می‌کند → teleprompter_push صدا می‌زند → پنجره‌ی overlay باز می‌شود
شما: کد را تایپ می‌کنید (در overlay یا در ویرایشگرتان)
سرور: پیشرفت را لحظه‌ای می‌سنجد → با اتمام، به OpenCode پیام می‌دهد
مدل: فایل را بررسی می‌کند، تست می‌زند، کار را تمام می‌کند
```

## اگر تازه‌کاری یا تازه وارد پروژه شدی

1. نصب یک‌خطی بالا را بزن (فقط همین یک دستور).
2. در OpenCode بگو `/tour` — مدل کل پروژه را می‌خواند و فایل‌به‌فایل با تایپ
   خودت جلو می‌بردت؛ یا بگو «پایتون را از صفر با تایپ یادم بده» (حالت پایه:
   خط‌های کوتاه + توضیحِ هر خط).
3. هر چه گفت همان‌جا تایپ کن؛ سؤال داشتی همان‌جا بپرس — جواب روی همان خط می‌آید.

## نصب (سراسری)

یک اسکریپت برای همه‌ی سطح‌ها — idempotent (اجرای دوباره بی‌خطر است):

```bash
./install.sh                      # همه: پلاگین، ادیتور، MCPها، اپ مک، آیتم لاگین
./install.sh --only opencode,vscode
./install.sh --only codex         # فقط MCP برای Codex CLI
./install.sh --status             # JSON وضعیت برای پنل مدیریت
./install.sh --electron           # + دانلود Electron (پنجره‌ی overlay)
./install.sh --no-login           # بدون آیتم شروع خودکار
./install.sh --app-out PATH       # جای Drill.app (پیش‌فرض /Applications)
```

| هدف | چه می‌کند |
|---|---|
| `opencode` | پلاگین + سرور + اوورلی در `~/.config/opencode/plugins/teleprompter` |
| `vscode` | افزونه در VS Code / Cursor / Windsurf (بعدش: Reload Window) |
| `codex` | بلوک `[mcp_servers.teleprompter]` در `~/.codex/config.toml` |
| `claude` | MCP در Claude Code (ترجیحاً با `claude mcp add --scope user`) |
| `gemini` | `mcpServers.teleprompter` در `~/.muse/settings.json` |
| `app` | ساخت `Drill.app` (آیکن، منوبار، امضای ad-hoc) + ثبت در Launchpad |
| `login` | آیتم شروع خودکار (LaunchAgent) برای اوورلی |

سپس OpenCode را یک‌بار ری‌استارت کنید تا پلاگین لود شود:

```bash
opencode service restart
```

همه‌ی این‌ها از **پنل مدیریت** (`/admin` → نصب و راه‌اندازی) هم تک‌تک قابل نصب و پایش‌اند.

> «این فیکس را به‌صورت تمرین تایپ بده»

ابزارهای پلاگین:

- **`teleprompter_push`** — کد نهایی، عنوان، هدف، فایل هدف و حالت را می‌فرستد
- **`teleprompter_status`** — درصد پیشرفت، وضعیت فایل و سرعت تمرین

حالت‌ها:

- `practice` — فقط تمرین تایپ داخل overlay
- `work` — کار واقعی: در ویرایشگر خودتان می‌نویسید، سرور با `fs.watch` پیشرفت را می‌بیند
- `both` — هر دو همزمان (پیش‌فرض)

## صفحه‌ی شروع و تنظیمات (Hub)

وقتی تمرینی فعال نیست، پنجره به‌جای پیامِ خالی یک **مرکز شروع و تنظیمات** نشان می‌دهد:

- **کارت اتصال‌ها با وضعیت زنده** — پلاگین OpenCode، افزونه‌ی VS Code و سرور MCP هر کدام
  با `POST /api/heartbeat {src}` خبر می‌دهند؛ کارتِ اخیر (کمتر از ۴۵ ثانیه) «Connected»
  وگرنه «Waiting…» نشان می‌دهد. اتصال‌ها بدون ری‌استارت خودبه‌خود روشن می‌شوند.
- **شروع سریع** — چهار گام نصب/استفاده با دستوراتِ کلیک‌برای‌کپی (`./install.sh`، `/drill …`).
- **تنظیمات** — زبان، اندازه‌ی متن، چیدمان پیش‌فرضِ تمرین‌ها (خودکار/پنل/نوار زیرنویس)،
  همیشه‌روی‌بالا (Electron) و باز کردن در مرورگر.
- **تمرین نمونه** — یک تمرین ۴خطی فوری برای دیدنِ کل مسیر (نوار زیرنویس + نظارت فایل).

### زبان رابط (i18n)

پیش‌فرض **انگلیسی** است؛ سوییچ `EN ⇄ فارسی` در هدرِ پنل و در تنظیمات هست (انتخاب در
`localStorage.tpLang` ذخیره می‌شود) و `dir` صفحه خودکار می‌چرخد (فارسی → RTL).

- همه‌ی متن‌های رابط در **`app/public/lang.js`** هستند: هر زبان یک بلوک
  `{ name, dir, s: { ... } }` در `window.TP_LANGS` است.
- **اضافه کردن زبان جدید** = فقط یک بلوک دیگر در `lang.js`؛ هیچ فایل دیگری دست نمی‌خورد.
- خبرهای سرور `key` + `params` دارند؛ رندرر اگر ترجمه داشته باشد همان را نشان می‌دهد،
  وگرنه همان `message` (انگلیسی) را.

## هدایتِ تایپ (Guided typing)

نکته‌ی اصلیِ محصول: مدل خروجی می‌دهد و OpenCode که کواوردینیتورِ مدل است، اینجا **کاربر را**
کواوردینیت می‌کند — کاربر جایِ مدل می‌نشیند، و می‌داند این تایپ برای چیست و قرار است چه نتیجه‌ای بدهد:

- **`result`** — یک جمله: وقتی تمرین تمام شد چه چیزی درست/ساخته می‌شود؛ آخرِ کار به‌شکلِ
  «نتیجه‌ی نهایی» کنار کد نمایش داده می‌شود.
- **`guide`** — ۲ تا ۵ گامِ `{from, to, why, result}`: کد به بلوک‌های منطقی تقسیم می‌شود و برای هر
  بلوک «چرا الان تایپ می‌شود» و «بعد از تایپ چه می‌کند» آمده است. با رسیدن به هر خط، جعبه‌ی
  **Why / Result** در پنل و نوار زیرنویس زنده عوض می‌شود (برچسب `lines x–y` همان خطوطِ گام است).
- **مقصد** (`targetFile:startLine`) از قبل مشخص است؛ پس کاربر هم‌زمان **جای**، **دلیل** و **نتیجه** را
  در لحظه‌ی تایپ می‌بیند.
- در **فازِ فایل** (تمرینِ تایپ تمام ولی فایل هنوز نوشته‌نشده) راهنما زنده می‌ماند: به‌محض گزارشِ
  خطی از ویرایشگر، راهنمایِ همان خط در نوار نمایش داده می‌شود.
- مدرسِ مدل `DRILL_GUIDE` (داخل پلاگین) است که همیشه `result` و `guide` بفرستد؛ سرور MCP هم همین
  فیلدها را در `teleprompter_push` می‌پذیرد. تمرینِ نمونه‌ی هاب همراه با راهنما ساخته می‌شود.

## پنل مدیریتی وب (`/admin`)

یک پنل وب دوزبانه (EN/FA، هم‌مسیر با هاب) برای تنظیمات، نصب و کارِ درست روی سیستم:

- **سیستم** — پلتفرم، نود، آپتایم، پورت، قفل توکن، فایل وضعیت (مسیر + حجم) و تیکِ نصبِ هر جزء
  (پلاگین OpenCode، افزونه‌ی VS Code، باینری Electron، بودنِ `install.sh`).
- **وضعیت زنده** — تمرین فعال (فایل:خط، پیشرفت فایل/تمرین، نتیجه‌ی verify)، طول صف، اعلان‌های نرسیده
  و سنِ heartbeat هر اتصال؛ دکمه‌های مرحله‌ی بعد، خالی کردن صف، reset جاری/کامل.
- **تمرین و صف** — فهرست صف با جایگاه + دکمه‌ی «تمرین آزمایشی» برای تستِ مسیر بدون OpenCode.
- **تنظیمات سرور** (ماندگار در همان state file): حالت تطبیق پیش‌فرض، سقف صف، نگه‌داشت اعلان‌ها،
  سقف پیش‌فرض verify. وقتی drill فیلدی را نفرستد، همین‌ها اعمال می‌شوند.
- **نصب و راه‌اندازی** — اجرای `install.sh` در پس‌زمینه با لاگِ زنده (همان لاگ قابل polling).
- **اعلان‌ها** — ۱۵ تای آخر با وضعیت verify و ack.
- اگر `TELEPROMPTER_TOKEN` ست باشد، پنل درگاه توکن می‌خواهد (همان توکن در `?token=` می‌ماند)؛
  رفرش خودکار هر ۵ ثانیه.

## گفت‌وگوی لنگردار به خط (annotate)

کاربر خط‌به‌خط تایپ می‌کند و ممکن است درباره‌ی یک خط سؤال کند («خط ۳ را توضیح بده»،
«خط ۵ را تمیزتر کن»). حلقه:

1. کاربر در جلسه می‌پرسد (با شماره‌ی خط).
2. مدل در چت جواب می‌دهد **و** با `teleprompter_note` (پلاگین) یا `teleprompter_note`
   (MCP) توضیح ۱-۲ جمله‌ای را به همان خط می‌چسباند: `{line, text, replace?}`.
3. یادداشت همان لحظه روی آن خط در اوورلی دیده می‌شود (جعبه‌ی Note در پنل؛ در نوار
   به‌جای «چرا» می‌نشیند) و با جلو رفتن تایپ عوض می‌شود.

- مدلِ خوب ۱-۲ خطِ سختِ هر تمرین را خودش پیشاپیش annotate می‌کند (فیلد `notes`
  در push هم همین شکل را می‌پذیرد: `[{line, text}]`).
- سقف ۶۰ یادداشت؛ خطِ بیرونِ بازه به نزدیک‌ترین خطِ معتبر می‌چسبد؛ متن خالی رد می‌شود.
- API: `POST /api/notes {notes:[...], replace?}`.

## اتاق فرمان (Mission control)

از داخل خودِ اپ (`/admin` → اتاق فرمان) می‌شود به مدلِ راهنما وصل شد، فایل را دید و
تایپ را جلو برد — بدون خروج از اپ:

- **محرک‌ها**: همه‌ی اتصال‌های زنده (پلاگین، افزونه، MCPها) با سنِ heartbeat و
  پرچم‌های سلامت؛ سؤال همیشه به راننده‌ی تمرینِ جاری می‌رسد.
- **پرسش**: جعبه‌ی متن → `POST /api/ask {text}` → مدل در جلسه جواب می‌دهد
  (پلاگین با اعلان می‌رساند؛ MCP در `teleprompter_wait` بعدی می‌گیرد).
- **نمایش فایل**: فقط-خواندنی، حول خط مقصد — `GET /api/file?path=&center=&context=`
  فقط فایل‌های شناخته‌شده‌ی drill/صف را نشان می‌دهد (مسیر دلخواه ۴۰۳ می‌گیرد).
- تایپِ تمرینی در همان تایپر اوورلی است؛ تایپِ واقعی در ویرایشگر با ghost.

## مدیریت تک‌نمونه‌ای (یک کاربر، یک میز)

ذات سیستم تک‌کاربره است و همان‌طور نگه داشته می‌شود:

- **یک سرور در هر پورت** (پیش‌فرض 4783؛ تست‌ها 4790) — دومی `EADDRINUSE` می‌گیرد.
- **یک اوورلی** — قفل single-instance الکترون؛ اجرای دوم فقط همان اولی را جلو می‌آورد.
- **یک تمرین فعال + صف** — pushهای هم‌زمان (حتی از جلسه‌های مختلف) در صف می‌نشینند؛
  اعلان هر تمرین به همان جلسه‌ای می‌رسد که آن را فرستاد.
- **جایگزینی خودکار کد کهنه** — سرور در `/api/state` و `/health` گزارش می‌دهد
  (`pid/startedAt/stale`)؛ اگر فایلِ روی دیسک از کدِ در حال اجرا تازه‌تر باشد
  (`stale:true`)، پلاگین در `ensureServer` بعدی خودش آن را با نمونه‌ی تازه عوض می‌کند.
  خاموشیِ دستی: `POST /api/shutdown {confirm:true}`.

## کار واقعی (Real work)

برای اینکه دریل فقط تمرین نباشد و کار واقعی را جلو ببرد:

- **صفِ تمرین‌ها** — وقتی تمرینی ناتمام است، `POST /api/drill` تازه‌وارد را **جایگزین نمی‌کند**؛
  در صف می‌نشیند (`{queued:true, position}`) و با تمام شدنِ جاری خودکار فعال می‌شود. کار چندمرحله‌ای
  = چند push پشتِ هم (هر مرحله یک `targetFile`). `force:true` یعنی «همین حالا جایگزین کن».
  `POST /api/next` پرش دستی، `POST /api/queue/clear` خالی کردن صف، `POST /api/reset {all:true}`
  پاک‌سازی کامل (بدون `all`، reset به مرحله‌ی بعد می‌رود).
- **ماندگاری** — تمرین، صف، پیشرفت و اعلان‌ها در `app/state-<port>.json` (دسترسی `0600`) ذخیره و با
  بالا آمدن بازیابی می‌شوند؛ نظارت فایل هم از سر گرفته می‌شود.
- **توکنِ محلی** — با `TELEPROMPTER_TOKEN` همه‌ی `/api`ها و `/events` هدر `Authorization: Bearer`
  یا `?token=` می‌خواهند. اوورلی (Electron)، پلاگین، MCP و افزونه‌ی VS Code خودکار همان را می‌فرستند؛
  بدون توکن رفتار مثل قبل است.
- **تطبیق lenient** — با `matchMode:"lenient"` تورفتگی نادیده گرفته می‌شود (محتوا باید همان باشد)؛
  پیش‌فرض `exact` آموزشی است.
- **راستی‌آزماییِ خودکار** — با `verify:{command, cwd?, timeoutSec?}` بعد از تکمیل فایل، دستور
  (مثلاً `pytest -q`) در پوشه‌ی فایل اجرا و نتیجه (`ok/code/output`) به اعلان و
  `progress.verification` می‌چسبد و به جلسه برمی‌گردد.
- **تحویل مطمئن اعلان** — اعلان‌ها `acked` می‌گیرند؛ پلاگین بعد از `session.synthetic` موفق
  `POST /api/notifications/ack {ids}` می‌زند. تحویل‌نشده‌ها در پول بعدی و بعد از ری‌استارت
  دوباره می‌رسند.

## کار واقعی در ویرایشگر (VS Code)

- با تمرینِ تازه که `targetFile` دارد، افزونه در ویرایشگر پیام می‌دهد:
  `"${title}" → file:line` با دکمه‌ی **Go to target** — همان «هدایت به جای خاص».
- اگر فایل هنوز ساخته نشده، `Go to target` (دستور `Teleprompter: Go to Target Line`) با تأیید
  صریحِ خودت یک فایل **خالی** می‌سازد و در خط مقصد بازش می‌کند؛ تایپ همچنان کاملاً با توست
  (ابزار هیچ خط کدی به فایل نمی‌نویسد).
- افزونه در هر heartbeat گزارش سلامت می‌فرستد (`drillSeen/targetOpen/stateOk/err`) و پنل
  مدیریت (`/admin`) همان را نشان می‌دهد — یعنی معلوم است ویرایشگر واقعاً چه می‌بیند، نه ادعا.

## لایه‌ی TUI در OpenCode

همزمان با پلاگین سرور، یک پلاگین سمت TUI هم لود می‌شود (`./tui` در package.json):

| چیز | کجا |
|---|---|
| وضعیت زنده `✍ 62٪ · 45wpm` | footer در جلسه و صفحه‌ی خانه (فقط وقتی تمرین فعال است) |
| `/teleprompter` یا `/tp` | نمایش وضعیت؛ با آرگومان: `open` \| `reset` \| `url` |
| `Ctrl+Alt+T` | آوردن پنجره‌ی overlay روی صفحه |
| توست + اعلان سیستمی | شروع تمرین جدید و پایان کار (هنگامی که ترمینال در پس‌زمینه است) |

همه‌ی این‌ها از palette (کلید `/` یا `Ctrl+P`) هم با گروه «Teleprompter» قابل جست‌وجو هستند.
لایه‌ی TUI فقط رابط است: سرور، ابزارها و اعلان به جلسه را همان پلاگین سرور انجام می‌دهد.

## رفتار پایان کار

وقتی (الف) فایل دقیقاً با کد تمرین برابر شود یا (ب) تمرین تایپ تمام شود،
سرور یک اعلان صف می‌کند و پلاگین آن را با `session.synthetic` در همان جلسه‌ی
OpenCode می‌فرستد؛ مدل خودش فایل را بررسی و تست می‌کند.

## نوار سیستم (Menu Bar / Tray)

پنجره‌ی overlay تنها ورودی نیست؛ یک **آیتم وضعیت** هم در نوار سیستم ساخته می‌شود
(بدون وابستگی جدید — از خود Electron):

| سیستم | چه می‌بینید |
|---|---|
| macOS | آیکن میکروفن + متن زنده `✍ 62% · 45wpm` کنار ساعت |
| ویندوز | آیکن در ناحیه اعلان کنار ساعت؛ پیشرفت در tooltip |
| لینوکس | آیکن سینی (بستگی به DE و پشتیبانی appindicator) |

- **کلیک چپ** → پنجره‌ی فشرده (~۴۷۰px) زیر همان آیکن باز می‌شود و با رفتن فوکوس
  خودش پنهان می‌شود (رفتار معمول اپ‌های menubar). اگر نوار زیرنویس باز باشد،
  یک کلیک آن را به همین پنل برمی‌گرداند.
- **کلیک راست** → منو: نمایش/پنهان، پنجره‌ی شناور، **نوار زیرنویس (چک‌باکس)**،
  پاک کردن تمرین، باز کردن در مرورگر، خروج.
- `Ctrl+Shift+P` مثل قبل پنجره‌ی شناور را toggle می‌کند و حالت شناور سر جایش
  می‌ماند — یعنی برای تمرین بلند، همچنان پنجره‌ی همیشه‌روی‌بالا را دارید.
- با `📌` پنلِ زیر آیکن «سنجاق» می‌شود و دیگر با رفتن فوکوس پنهان نمی‌شود.

آیکن‌ها را `tools/make_tray_icon.py` (فقط کتابخانه‌ی استاندارد پایتون) می‌سازد.

## نوار زیرنویس (حالت Subtitle)

مثل زیرنویسِ فیلم: یک نوار شناور، بدون قاب و بدون پنل که فقط
خطِ جاری را بزرگ و سفید (با سایه‌ی خوانا روی هر پس‌زمینه‌ای) و خطِ بعد را کم‌رنگ
نشان می‌دهد. نه فوکوسی از ویرایشگرتان گرفته می‌شود
(پنجره عمداً `focusable=false` است) — یعنی هنگام تایپ، تمرکز و کلیدها همچنان
دستِ خودتان است.

- **جا**: پیش‌فرض **بالای صفحه** (زیر منوبار)؛ با دکمه‌ی `⇅` در خودِ نوار بین بالا/پایین
  سوییچ می‌شود و انتخاب می‌ماند (`tpSubPos`).
- **جابه‌جایی**: نوارِ خاکستریِ بالای نوار (`sub-drag`) را بگیرید و بکشید.
- **ریسایز**: دستگیره‌ی `⤡` پایین-چپِ نوار را درگ کنید؛ اندازه زنده عوض و ذخیره می‌شود
  (`tpSubSize`) و با سوییچ پنل/نوار هم حفظ می‌ماند. خطِ جاریِ بلند به‌جای `…` تا ۳ سطر
  می‌شکند تا آخرش دیده شود.

نکته‌ی اصلی: **اسکرول با تایپِ شما جلو می‌رود**، نه با زمان:

| منبع حرکت | از کجا می‌آید |
|---|---|
| مکان‌نما در ویرایشگر | افزونه‌ی VS Code هر بار جابه‌جاییِ cursor را به `POST /api/progress` می‌فرستد |
| ذخیره‌شدنِ فایل هدف | همان watcher همیشگی سرور (`fs.watchFile`) |
| تایپ داخل پنجره‌ی تمرین | خود رندرر، با هر کلید |

هرکدام **آخرین فعالیت** را داشته باشد، نوار همان جریان را دنبال می‌کند — یعنی
کافی است در VS Code کلیک کنید و تایپ کنید؛ زیرنویس خطِ دقیقاً زیر مکان‌نمایتان
را نشان می‌دهد.

- **خودکار**: تمرین‌های حالت `work` و `both` به‌صورت خودکار در این حالت باز می‌شوند؛
  حالت `practice` (تایپ داخل پنجره) پنل کامل را می‌خواهد و همان باز می‌شود.
- **دستی**: دکمه‌ی `🎞` در پنل یا `⌨` در نوار (یا چک‌باکس منوی ترِی) بین دو حالت
  جابه‌جا می‌کند؛ انتخاب‌تان برای همان تمرین ذخیره می‌شود.
- نوار با `Esc` یا `✕` پنهان می‌شود؛ نوارِ بالای آن برای جابه‌جایی کشیدنی است.
- متریک ریزِ پایین: `خط/کل · درصد · سرعت`.
- **مقصد و دلیل**: خطِ آبیِ پایین `file.py:12` یعنی «دقیقاً از همین خط بنویس»
  (hover مسیر کامل را می‌دهد) و زیرِ عنوان همان `goal` است — یعنی *چرا* این کد
  لازم است — تا کاربر هنگام تایپ هم تایپ یاد بگیرد هم پشتِ کد فکر کردن را.
- `startLine` را خودِ مدل هنگام `push` می‌فرستد؛ نوار، پنل، ghost در ویرایشگر و
  نظارتِ فایل همه از همان خطِ مقصد استفاده می‌کنند.

## اتصال عوامل دیگر (MCP)

برای **Claude Code**، **Codex CLI**، **Gemini CLI** و هر کلاینت MCP، یک سرور stdio
بدون وابستگی وجود دارد که همان سرور محلی را راه می‌اندازد و چهار ابزار می‌دهد:

| ابزار | کار |
|---|---|
| `teleprompter_push` | فرستادن کد برای تایپ کاربر (دقیقاً همان پیام `push` پلاگین) |
| `teleprompter_status` | درصد، سرعت، وضعیت فایل |
| `teleprompter_wait` | **بلوکه تا اتمام کاربر** (۵ تا ۳۰۰ ثانیه) — جایگزین پیام synthetic |
| `teleprompter_reset` | پاک کردن تمرین فعلی |

چون Claude Code و Codex پیام synthetic ندارند، جریان کار این است:
`push` → `wait` (تا خبر اتمام برسد) → ادامه‌ی کار.

### Claude Code

```bash
claude mcp add --scope user teleprompter -- node ~/.config/opencode/plugins/teleprompter/app/mcp.mjs
```

(یا در `~/.claude.json` / `.mcp.json` پروژه:) `{"mcpServers":{"teleprompter":{"command":"node","args":["~/.config/opencode/plugins/teleprompter/app/mcp.mjs"]}}}`

اگر `wait` بلند می‌خواهید، timeout ابزار را بالا ببرید: `MCP_TOOL_TIMEOUT=320 claude`

### Codex CLI

```bash
codex mcp add teleprompter -- node ~/.config/opencode/plugins/teleprompter/app/mcp.mjs
```

یا دستی در `~/.codex/config.toml`:

```toml
[mcp_servers.teleprompter]
command = "node"
args = ["~/.config/opencode/plugins/teleprompter/app/mcp.mjs"]
```

### Gemini CLI

در `~/.gemini/settings.json`:

```json
{ "mcpServers": { "teleprompter": { "command": "node",
  "args": ["~/.config/opencode/plugins/teleprompter/app/mcp.mjs"] } } }
```

### OpenCode (جایگزین پلاگین)

```bash
opencode mcp add teleprompter -- node ~/.config/opencode/plugins/teleprompter/app/mcp.mjs
```

## API سرور

```
GET  /api/state                      وضعیت کامل (+ integrations: آخرین heartbeat هر سطح)
POST /api/drill                      {title, goal, language, code, targetFile?, startLine?, mode, hints?, result?, guide?, matchMode?, verify?, force?} — اگر تمرینِ ناتمام باشد، در صف می‌نشیند ({queued, position})
POST /api/next                       پرش به مرحله‌ی بعدِ صف
POST /api/queue/clear                خالی کردن صف
POST /api/notifications/ack          {ids:[...]} تأیید تحویل اعلان‌ها
POST /api/notes                      {notes:[{line,text}], replace?} یادداشت لنگردار به خط
POST /api/ask                        {text} پرسش از مدل راهنما (اتاق فرمان)
GET  /api/ask                        سؤال‌های بی‌پاسخ
POST /api/ask/ack                    {ids:[...]} تأیید تحویل سؤال
GET  /api/file?path=&center=&context=  نمای فقط-خواندنی فایل تمرین (فقط مسیر شناخته‌شده)
GET  /api/admin/system               وضعیت سیستم + تیک نصب اجزا + وضعیت زنده
GET  /api/admin/settings              خواندن تنظیمات سرور
POST /api/admin/settings              {defaultMatchMode?, queueMax?, notifyMax?, verifyTimeoutSec?}
POST /api/admin/install               اجرای install.sh در پس‌زمینه
GET  /api/admin/install/log           دنباله‌ی لاگ نصب
POST /api/progress                   {practice:{matched, keys, correct, wpm}} یا {cursor: خطِ خام فایل}
POST /api/complete                   {by:"practice"|"file"}
POST /api/heartbeat                  {src:"opencode"|"vscode"|"mcp"} گزارشِ زنده بودن (کارت اتصال‌ها)
POST /api/open                       آوردن پنجره‌ی overlay روی صفحه (از TUI با Ctrl+Alt+T)
POST /api/reset                      پاک کردن تمرین
GET  /api/notifications?since=<ms>   اعلان‌های پایان کار (پولینگ پلاگین/MCP)
GET  /events                         جریان SSE برای رابط کاربری
```

متغیرهای محیطی: `TELEPROMPTER_PORT` (پیش‌فرض 4783) و `TELEPROMPTER_NO_OPEN=1`
(جلوگیری از باز شدن خودکار پنجره).

## کلیدهای میانبر در overlay

- `Enter` — رفتن به خط بعد (وقتی خط درست تایپ شده باشد)
- `Tab` — پرش به تورگذاری مورد انتظار خط
- `Esc` — پنهان کردن پنجره/نوار زیرنویس
- `A+` / `A−` — اندازه‌ی فونت
- `🎞` — سوییچ پنل ⇄ نوار زیرنویس (در نوار: `⌨` برمی‌گرداند به پنل)
- `📌` — سنجاق (همیشه‌روی‌بالا + پنلِ ترِی با فوکوس پنهان نمی‌شود)
- `Ctrl+Shift+P` — نمایش/مخفی کردن سراسری (Electron)

## اتصال به ویرایشگرهای دلخواه

نظارت روی فایل به هیچ افزونه‌ای نیاز ندارد: هر ویرایشگری (VS Code, Vim, Zed, …)
که فایل هدف را بنویسد، پیشرفت ثبت می‌شود. ابزارهای دیگر هم می‌توانند مستقیم
`POST /api/progress` بزنند — پروتکل HTTP ساده و محلی است. اگر همان ابزار
`{"cursor": <شماره‌ی خط>}` هم بفرستد، نوار زیرنویس با مکان‌نما جلو می‌رود.

### افزونه‌ی VS Code: دریل داخل جای تایپ

اگر می‌خواهید دریل **داخل خود ویرایشگر و دقیقاً کنار مکان‌نما** باشد،
`vscode-extension/` را دارد — یک فایل جافایل ساده، بدون وابستگی و بدون build:

- **متن ghost کدرنگ** از همان خطِ مورد انتظار کنار مکان‌نما می‌آید و با تایپِ
  درست جلو می‌رود؛ به‌محض غلط شدن پنهان می‌شود (دیف را پنل کناری نشان می‌دهد).
  جای‌گذاری با `startLine` انجام می‌شود: خط ۱۲ فایل = خط ۱ تمرین.
- **نوار وضعیت** `62% · 45wpm` زنده در پایین VS Code (tooltip: `file:line`).
- **مکان‌نما را گزارش می‌کند** → نوار زیرنویسِ شناور خطِ زیر cursor را نشان می‌دهد
  (فقط درون بلوکِ مقصد).
- **اعلان** هنگام اتمام تمرین + دستورها: `Show Window` / `Show Status` /
  `Reset Drill` و `Go to Target Line` (پرش به خطِ مقصد). هنگام رسیدن تمرینِ جدید،
  اگر فایل مقصد باز باشد خودش بدون دزدیدن فوکوس به خطِ مقصد می‌رود.

نصب با همان `./install.sh` انجام می‌شود (خودش `~/.vscode/extensions`،
`~/.vscode-server/extensions`، `~/.cursor/extensions` و `~/.windsurf/extensions`
را می‌بیند) و بعد در ویرایشگر: `Developer: Reload Window`.

اگر ghost را ندیدید `editor.inlineSuggest.enabled` روشن باشد. برای Neovim همین
الگو با متن مجازی (`virt_text`) قابل تکرار است — بگویید تا بسازم.
